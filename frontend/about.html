Mission

Bridging communication through AI

Over 70 million deaf people worldwide use sign language as their primary means of communication. This project demonstrates how computer vision and deep learning can help bridge the communication gap — providing a fast, accessible, and highly accurate tool for real-time ASL letter recognition that works on any standard laptop or PC, no specialized hardware required.

🖐

MediaPipe Hands

Google's MediaPipe Tasks API extracts 21 precise 3D hand landmarks per frame in real-time — running at 25+ FPS on CPU. Only clean, confident detections (~63,580 of 87,000 images) were used for training, ensuring high data quality.

🧠

Keras Neural Network

A 4-layer dense network (512→256→128→64→26) with BatchNormalization, Dropout, and L2 regularization classifies 63 normalized landmark coordinates into 26 ASL letters — achieving 99.18% test accuracy in under 2 milliseconds.

📈

Data Augmentation

Training data was augmented 3× using Gaussian noise, random scale jitter (±10%), and 2D rotation (±15°) — expanding 45,430 training samples to 181,720 and making the model robust to real-world variation.

⚡

FastAPI Inference

A production-grade REST API built with FastAPI accepts image uploads or raw landmarks and returns the predicted letter, confidence score, top-5 alternatives, landmark coordinates, and timing — all in a single JSON response.

♿

Accessibility Focus

The word builder feature allows users to sign complete words and sentences by holding each sign steadily for 1.2 seconds — making the tool genuinely useful as an assistive communication aid.

💻

CPU Optimized

Every design choice — landmark-based input instead of raw pixels, compact model size, efficient inference loop — is optimized for CPU. The model processes 8+ predictions per second on a standard laptop without any GPU.

How it works

End-to-end pipeline

1

Webcam frame capture

The browser captures frames at ~8 predictions per second using the MediaStream API. Each frame is JPEG-compressed and sent to the FastAPI server via POST /api/predict.

2

Hand detection — MediaPipe Tasks API

MediaPipe HandLandmarker detects the hand and extracts 21 landmarks in 3D space (x, y, z per point = 63 floats). If no hand is detected, the API immediately returns hand_detected: false.

3

Wrist-centered normalization

All 21 landmarks are centered on the wrist (landmark 0) and scaled by the wrist-to-middle-MCP distance (landmark 9). This makes predictions fully invariant to hand size and position in the frame.

4

Keras classification — 99.18% accuracy

The normalized 63-float vector passes through the dense network (512→256→128→64→Softmax 26). The model outputs probability scores for all 26 ASL letters. Trained with cosine LR decay, label smoothing, and class weights.

5

Result rendering

The predicted letter, confidence, top-5 alternatives, and 21 landmark coordinates are returned as JSON. The frontend renders the letter overlay, draws the hand skeleton on canvas, and updates the confidence bars in real-time.

6

Word builder

When the same letter is detected consistently for 1.2 seconds, it is committed to the word builder. Users can build complete words, save them to history, and clear or backspace as needed.

Dataset

ASL Alphabet — Kaggle

Training data sourced from the ASL Alphabet dataset on Kaggle — 87,000 images across 29 classes (A–Z plus del, nothing, space). MediaPipe HandLandmarker was run over each image to extract 21 landmark coordinates, converting the raw image dataset into a 63-feature CSV. Classes with insufficient detections (nothing) and motion-dependent letters (J, Z) were excluded, leaving 58,665 clean samples across 26 classes. Training data was augmented 3× to 181,720 samples.

Known limitations & mitigations

Honest caveats

Unresolved J and Z not supported
These letters require hand motion — impossible to classify from a single static landmark snapshot. A future LSTM-based temporal model using sequences of frames would resolve this.
Mitigated N and M confusion
N (2 fingers over thumb) and M (3 fingers over thumb) are visually similar in static pose. Fixed in frontend: when model confidence is below 92%, a geometric check counts curled fingers using landmark y-coordinates to distinguish N from M — reducing confusion without any model retraining.
Mitigated Lighting sensitivity
MediaPipe detection drops in poor lighting. Fixed in frontend: the app analyzes frame brightness every 3 seconds. When brightness drops below threshold, an amber warning banner appears on the camera feed — preventing silent failures.
Future work Single hand only
The model processes one hand at a time. Two-handed ASL signs require dual-stream landmark extraction and a fusion model — planned as a future enhancement.
